# RevoPhone 批量进货

把用户的需求制作成真正可导入 RevoPhone 的商品文件。适配 RevoPhone 1.1.8 的 `revophone-mall-items` v1 格式；不依赖项目源码、浏览器或额外模型接口，只需 Codex 和 Node.js。

## 制作商品

先读 [商品字段与实际效果](references/item-contract.md)。确定数量、分类、主题、价格及用户给出的尺寸／身体类型／能力限制。用户已授权自由设计时可补齐未规定的设计；仅要求整理现成资料时原样转写，缺少必填信息再询问。分类可混合。

- 本轮明确要求优先；用户给出的参考资料和有效预设为依据。没有规定的尺寸不另设一套固定范围，不把未设定身体类型统一当成扶她。
- 用户给出异构预设文件时，用下方 `rules` 命令提取比例尺、分类工作台和当前姿势。使用启用的条目；关闭、清空或缺失时不回填默认规则。预设可从「预设 → 异构 → 对应预设的更多菜单 → 导出」取得。
- 参考图可用于外观设计，但不会被装入商品包；图看不到时说明缺少依据，不声称已经识图。
- 区分身体类型、下体覆盖与能力条件。肉躯分别填写静息、前方和后方延展；新能力是剧情设定，不承诺执行未实现的数值、脚本、冷却或计时器。
- 这里由当前 Codex 会话制作，不再向商城设计模型发请求。手机进货的前置 user／assistant 对话属于手机请求协议，不在技能里伪装成真实消息，也不复制其中的越权声明。

直接编写 UTF-8 商品草稿 JSON（数组或包含 `items` 的对象），不只在回复里列点子。名称、描述和能力应有实质差异，满足指定总数和分类配额。大批量可以分段制作后合并校验，最终给出一个导入文件；目录上限仍然是 200，分文件不会扩大库存容量。

## 打包与核对

以下路径相对本技能目录；运行时用技能的实际绝对路径，不假定当前工作目录。

```powershell
node "<skill-dir>/scripts/mall-pack.mjs" rules --input "<异构预设.json>"
node "<skill-dir>/scripts/mall-pack.mjs" pack --input "<商品草稿.json>" --output "<商城进货.json>"
node "<skill-dir>/scripts/mall-pack.mjs" check --input "<商城进货.json>"
```

用户提供了商城「导出全部商品文件」时，给 `pack` 和 `check` 增加 `--catalog "<全部商品.json>"`，核对新增数量、200 件上限、现有编号和同名冲突。只有进货单品的导出不能代表完整目录；未取得完整目录时如实说明容量／本地冲突尚未核对，不要求每次都先导出才能制作。

脚本会分配缺失 ID、补齐必要状态、阻止字段截断及错误枚举，去掉图片、购买状态和剧情记录，不覆盖已存在的输出文件。后续修改同一批商品以**已打包文件**为输入，保留 ID；重试时沿用成品，不重新给同批商品分配编号。不要把内置商品、自制衣柜或角色转化物品重新打包成进货。

修改现有商品从完整导出条目开始，保留未要求修改的设定；这个打包格式不是只传名称、价格的局部更新协议。

交付前检查条数与用户配额、价格、身体类型、能力条件以及设计和生图标签的一致性。脚本只验证结构，不能判断主题质量或任意自然语言比例尺是否满足。

## 交付与导入

给出最终 JSON 的文件链接、总数、分类分布、价格范围及结构校验结果。若未核对本地完整目录，说明这一项；文件生成不等于已经导入。

导入路径：**购物商城 → ＋ 进货上架 → 批量导入/导出 → 从 JSON 文件导入**，也可粘贴文件内容。普通上新保持「覆盖替换现有进货单品」不勾选。该选项会替换其他进货，只有用户明确需要整批替换时才使用。

商品包不含图片；导入后可逐件上传或另行生图。省略 `owned` 让新商品默认为未购买，重复导入同 ID 时保留本地购买状态；已有同 ID 图片也由商城保留。不要执行真实导入、购买、绘图或上传 GitHub，除非用户另外要求。
