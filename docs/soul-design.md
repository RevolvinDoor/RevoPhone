# Soul 设计合同（1.4.0 首版，1.4.2 修订）

用户已在当前会话确认设计并授权实施。现有聊天 App 显示名改为 Soul，保留内部 chat 标识和既有聊天能力，新增发现页。

- 原创、明确成年的陌生人，符合当前世界观；按需求或随机发现。
- 刷新一次：一条文字请求产生三份简单资料，每人一次全身照片请求。明确条件和排除项应用于每个人，未指定部分才随机补充；要求参与当前世界书扫描。
- 主动来信为按钮：一次产生一位新陌生人的简单资料、照片和招呼。性格积极配合，仍按其身份和世界条件行动。
- NSFW 独立开关（1.4.2 用户修正）：偏向成年写真创作者与性感穿搭博主的主页，签名、介绍、交友目的和非露骨写真共同体现差异；普通模式为日常交友与生活照。没有定时主动联系。
- 新人物保存发现时的要求和模式，补画、扩写与私聊沿用；切换开关仅影响下一次发现或来信，已有资料保留。要求是创作条件，不是人物知道的玩家信息。
- 简单资料包含姓名/昵称、年龄、性别、种族、地区、职业、兴趣、签名、介绍、交友目的、择友偏好与固定外貌依据。
- 喜欢/接受后才扩写完整人设、登记角色和角色状态，并进入私聊。发现角色附首句招呼；来信角色继续已有招呼，不重复生图或扩写。
- 对方仅接收玩家公开主页和双方自己的对话，不接收玩家私密人设、正文经历、其他联系人的对话或跨会话记忆。
- 每段正文聊天独立保存发现、来信、人物档案和私聊；旧聊天恢复、新聊天重新开始、删除正文聊天清理。旧版记录保留可导入。
- 公开主页独立填写；默认模板自动带入各聊天副本，支持多个模板，当前修改与默认模板分离。

维护源：core/soul.js（纯数据/提示词）、core/backend-soul.js（存档与登记）、host-soul.js（生成）、ui/soul.js / ui/soul.css（发现与主页）；现有聊天和存档按最小接口接入。所有模型数据转义，图片使用本地媒体和经过验证的数据 URL。

首版退出：模拟生成、隔离、恢复/删除、重试/重复点击、隐私请求组装和 UI 交互检查通过；静态差异与版本一致；不调用真实付费接口，不生成预览 HTML，不修改宿主。真实游玩由用户验收。按已有授权提交并推送 1.4.0。
